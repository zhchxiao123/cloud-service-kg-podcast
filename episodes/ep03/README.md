# EP03｜先问问题，再画本体：Competency Questions

## 学习目标

- 把模糊业务需求改写为具体、可验证的 CQ。
- 区分 Must-have、Should-have 和 Nice-to-have CQ。
- 从 CQ 中识别候选概念、关系、属性和约束。

## 核心知识点

- CQ 同时承担需求、范围和验收标准三种职责。
- 好 CQ 应具体、有边界、能用数据回答且答案可验证。
- 名词、关系、限定条件和输出形式分别提供不同建模信号。
- CQ 应追踪到数据来源、查询模板和预期答案。

## 演示素材

- 把“帮我选择 GPU 云服务”改写为三条可测试 CQ。
- 建立 CQ → 本体元素 → 数据需求 → 查询测试映射。

## 课后作业

> 为熟悉的领域写 5 条 CQ，标注优先级、答案形式和所需数据，并删除所有未定义的“最好”“合适”等词。
